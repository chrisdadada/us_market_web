> 状态：仅完成 dev 验收和 prod 只读核对。本文不是 prod 操作授权，不得据此自动部署、复制媒体或修改数据库。

## 当前判断

- dev 的 28 门视频已全部使用三档离线 HLS，原视频均可读取，可回滚。
- HLS 能显著减少完整观看流量，但会增加存储；这是流量成本与存储成本之间的交换。
- prod 暂不放行。长视频冷启动和大跨度拖动仍出现十几秒缓冲，且 4 门课程的 dev 转码源与 prod 当前视频不是同一字节文件。

## 精确存储与流量

数据来自 dev COS 实际对象大小，不是按码率估算；表内 GB 按 10 亿字节计算：

| 项目 | 实际大小 | 相对原视频 |

| 完整观看全部课程，1080p | 8.32 GB | 节省 47.05% |

用户播放时只下载一个清晰度，不会同时下载三档。实际流量还会受用户观看进度、重复拖动、播放器预加载和缓存命中影响。

## 回滚与 Prod 对应

- dev 28 个 `video_source_key` 均通过 Range 读取，原视频总计 15,712,674,311 字节。
- dev 与 prod 的 28 门课程按“课程名称 + 课时名称”全部一一对应，没有缺项或多项。
- dev 课时 35 对应 prod 课时 29；dev 课时 36 对应 prod 课时 30；其余课时 ID 相同。
- dev 和 prod 使用不同 COS 存储，prod 不能直接依赖 `lesson/hls/dev-*` 地址。
- 24 门课程的 dev 转码源与 prod 当前视频字节一致。
- prod 课时 6、8、10、25 与 dev 转码源时长和分辨率一致，但字节不一致。为失败关闭，这 4 门必须从 prod 当前 `video_key` 重新转码，不能直接复用 dev HLS。

## Prod 切换清单

以下步骤必须在用户当次明确授权后执行，并且每一步失败立即停止：

1. 固定待发布提交，先部署支持 HLS 的后端和前端代码，不修改课程数据；确认原 MP4 播放仍正常。
2. 为 prod 使用独立前缀 `lesson/hls/prod/<rollout-id>/lesson-<prod-id>/`，不得引用 dev 前缀。
3. 将 24 门字节一致课程的已验证 HLS 跨桶复制到 prod 前缀；逐对象核对大小和内容摘要。
4. 从 prod 当前视频重新转码课时 6、8、10、25；不得使用 dev 源文件代替。
5. 为每门课核对主清单、三档子清单、分片数量、总时长、首段/中段/末段 Range 和鉴权。
6. 在切换前冻结一份只含目标课程媒体字段的不可变回滚清单，记录当前 `video_key`、`video_source_key`、`video_output_key`、任务字段和行摘要。
7. 单个事务只更新目标课时的 `video_key` 与 `video_output_key`；保留现有 `video_source_key` 和历史任务字段，不覆盖媒体来源记录。
8. 切换后立即抽查 6 个有视频的课程系列，覆盖首播、拖动、尾段、无权限访问和签名过期。
9. 若任一课程失败，按回滚清单恢复原 `video_key` 与 `video_output_key`；不删除新 HLS，先恢复用户播放。
10. 发布前后核对 `open_portfolio_trades` 与 `open_portfolio_symbol_rules` 的行数、内容指纹和自增序列；普通课程发布不得打开或改写 prod `product.db`。
