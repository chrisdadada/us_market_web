# 代码管理基线

更新时间：2026-08-22

## 唯一发布基线

- `codex/dev-integration`：唯一允许发布 dev 代码的累计分支。
- `master`：仅接收已经在 dev 验收、准备进入 production 的稳定代码。
- 功能分支不得直接发布，也不得用旧工作树覆盖 dev。
- 旧分支的提交不得直接整批 cherry-pick；先与当前集成分支比较，只重新实现仍然缺失且已确认的部分。

## 当前遗留分支判定

以下功能在集成分支已有等价或更新实现，不再从旧分支合并：

- FOMC 日历刷新失败时保留已有数据。
- 纳指定投的数据保留、信号校准和每日估算。
- 市场区间、定投权限和页面文案测试。
- 已确认导航及旧版页面迁移。
- dev 发布分支、累计提交和公开版本校验。

以下内容继续隔离，不得混入普通发布：

- 课程媒体盘点、迁移和 COS 操作：继续使用独立媒体任务，prod 操作仍需当次授权。
- 关键点位的突破、回踩确认：属于新的用户可见业务口径，先出高保真图并确认，再基于集成分支重新实现。

## 发布前检查

1. 用 `git worktree list` 找到 `codex/dev-integration` 对应工作树。
2. 确认工作树无未提交的 tracked 文件。
3. 确认功能提交已经进入 `codex/dev-integration`。
4. 前端小改用 `scripts/release_dev_fast.sh`，其余用 `scripts/release_dev.sh`。
5. 不直接调用局部前台或后台部署；旧入口会自动转到完整累计发布。
6. production 仍需用户当次明确授权。

## 清理规则

- 尚未确认前不删除旧工作树或分支。
- 确认某分支已被集成或替代后，再单独清理对应工作树和本地分支。
- 清理只减少旧入口，不修改 dev / prod 数据和线上状态。
